## 2. Legado 规则语法备忘（迁移用）

- CSS 选择器 = **jsoup 语法**：`tag.class`、`#id`、`[attr=val]`、`a[href*=/chapters/]` 等都可用；属性取值用 `@href` `@text` `@html` `@src` `@content` `@data-original`。
- 正文多段：官方行为是多个匹配元素/多段 **按 `\n` 拼接**（`ruleContent.content` 匹配到的元素全部拼接）。
- JS：规则值以 `@js:` 开头或整段用 `<js>...</js>`；JS 环境提供 `java.ajax(url)`（GET 请求返回字符串）、`JSON.parse`、`baseUrl`、`book`、`source` 等；复杂 HTML 再造可用 `org.jsoup.Jsoup.parse(html).select(...)` 得到元素列表再交给 `chapterName`/`chapterUrl` 的 CSS 规则。
- 目录翻页：`ruleToc.nextTocUrl` 是**在当前目录页上找"下一页"链接的 CSS 选择器**（不是 URL 模板）；站点不给翻页链接时只能 `chapterList` 用 `@js:` 自己循环翻页。
- 清洗：`ruleContent.replaceRegex`（对正文文本做正则替换）适合去掉广告水印段；元素级清洗用 `@js:`/`<js>`。
- 请求头：书源 `header` 字段可全局带 `Referer`/`Cookie`/`UA`；Legado 无逐源"延迟"字段，秒级限速只能靠调低全局并发 + 减少单章请求次数来规避。
- 二进制/非 JSON 响应：`java.ajax` 返回字符串，Protobuf 等二进制格式 Legado 原生 JS 无法直接解析，必须走 `webJs`（注入浏览器环境 fetch + 二进制解码）或放弃该 API 流。

## 3. 分站点笔记

### 2.1 comick.dev（漫画站，REST JSON API）

**源码证据**：GooglyBlox/comick-source-api `src/lib/scrapers/comix.ts`（注意：该文件是 comix.to 的 scraper，但 GooglyBlox/comick-rss 仓库 README 明确声明"uses the Comick.dev API"；comick.dev 的公开 API 结构可从 comix.ts 的 API 调用模式推断）。

**URL 模式**
- 搜索/发现：`https://api.comick.dev/v1.0/comics?q={query}&limit=10`（推断自 comix.ts `search()` 里的 `${this.apiBase}/manga?keyword=` 模式）
- 详情页：`https://comick.dev/comic/{slug}` 或 `https://comick.dev/title/{hash_id}-{slug}`
- 章节列表 API：`https://api.comick.dev/v1.0/comic/{hash_id}/chapters?order[number]=desc&limit=100&page={N}`
- 章节内容 API：`https://api.comick.dev/v1.0/comic/{slug}/pages?chapter={chapter_id}`（推断）

**章节列表定位**
- 纯 API 流：`/comic/{hash_id}/chapters` 返回 JSON，每项含 `chapter_id`、`number`、`name`、`scanlation_group`
- 分页：`limit=100&page=N`，直到 `pagination.last_page`（源码实证：comick-source-api `comix.ts` `getChapterList()` 循环 `currentPage < pagination.last_page`）

**正文定位**
- 图片漫画站，Legado 书源对漫画支持有限；若要做，`ruleContent.content` 无法直接处理图片列表
- 若只做信息类书源（目录/元信息），API 返回 `poster.large`、`title`、`description`、`chapter_updated_at` 等字段足够

**反爬与坑**
- 无反爬迹象（公仓直接 fetch，无 UA 伪装、无 token）
- 速率限制：comick.dev 公开 API 未认证限速不明确，建议 500ms/请求

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://comick.dev",
  "ruleBookInfo": {
    "name": "@js:JSON.parse(java.ajax('https://api.comick.dev/v1.0/comics?q=' + encodeURIComponent(baseUrl.split('/').pop()))).result.items[0].title",
    "coverUrl": "@js:JSON.parse(java.ajax('https://api.comick.dev/v1.0/comics?q=' + encodeURIComponent(baseUrl.split('/').pop()))).result.items[0].poster.large",
    "tocUrl": ""
  },
  "ruleToc": {
    "chapterList": "@js:\nlet hashId = baseUrl.match(/\\/(?:comic|title)\\/([^/]+)/)[1].split('-')[0];\nlet chapters = [];\nlet page = 1;\nfor(;;) {\n  let res = JSON.parse(java.ajax('https://api.comick.dev/v1.0/comic/' + hashId + '/chapters?order[number]=desc&limit=100&page=' + page));\n  if(!res.result || !res.result.items || res.result.items.length === 0) break;\n  for(let c of res.result.items) {\n    chapters.push('<a href=\"' + 'https://comick.dev/title/' + hashId + '-' + res.result.slug + '/' + c.chapter_id + '-chapter-' + c.number + '\">' + (c.name || 'Chapter ' + c.number) + '</a>');\n  }\n  if(page >= res.result.pagination.last_page) break;\n  page++;\n}\nresult = org.jsoup.Jsoup.parse(chapters.join('')).select('a');",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": {
    "content": "@js:java.ajax('https://api.comick.dev/v1.0/comic/' + slug + '/pages?chapter=' + chapterId)"
  }
}
```
- **待实测**：comick.dev 的图片 URL 是否允许直接外链；Legado 对漫画图片阅读器的支持程度。
- 该站更适合做"信息查询"类书源，而非完整漫画阅读书源。

### 2.2 mangaplus.shueisha.co.jp（官方漫画 API，Protobuf）

**源码证据**：
- hurlenko/mloader `mloader/loader.py`：`_api_url = "https://jumpg-webapi.tokyo-cdn.com"`，调用 `/api/manga_viewer` 和 `/api/title_detailV3`，解析 Protobuf `Response.FromString(resp.content)`
- hyugogirubato/mangaplus `mangaplus/shueisha.py`：`api = 'https://jumpg-api.tokyo-cdn.com/api'`，详细实现 `getMangaData`、`getTitleDetail`、`getAllTitlesV3` 等方法，`proto2dict(r.content)` 解码
- akitaonrails/frank_mangaplus `reader/api/src/client.rs`：`API_HOST = "jumpg-api.tokyo-cdn.com"`，`APP_VER = "250"`，`OS_VER_DEFAULT = "36"`

**URL 模式**
- API 基础 URL：`https://jumpg-api.tokyo-cdn.com/api` 或 `https://jumpg-webapi.tokyo-cdn.com`（两个域名均见于源码）
- 标题详情：`GET /api/title_detailV3?title_id={id}&lang=eng&clang=eng`（Protobuf 二进制）
- 章节内容：`GET /api/manga_viewer?chapter_id={id}&split=yes&img_quality=super_high`（Protobuf 二进制）
- 搜索：`GET /api/title_list/search?lang=eng&clang=eng`（Protobuf 二进制）
- 首页/更新：`GET /api/home_v6?lang=eng&viewer_mode=vertical&clang=eng`

**章节列表定位**
- `title_detailV3` 返回 `chapter_list_group`，每组有 `first_chapter_list` 和 `last_chapter_list`，每项含 `chapter_id`、`name`（源码实证：mloader `loader.py` 第 89-96 行 `chain(group.first_chapter_list, group.last_chapter_list)`）
- 章节 ID 是整数，URL 无标准网页形态（官方 App 内嵌 WebView）

**正文定位**
- `manga_viewer` 返回 `pages[]`，每项含 `manga_page.image_url`、`encryption_key`（XOR 加密）
- 图片需 XOR 解密：`key = bytes.fromhex(encryption_hex); data[i] ^= key[i % len(key)]`（源码实证：mloader `loader.py` `_decrypt_image` 方法）

**反爬与坑**
- **Protobuf 二进制**：响应不是 JSON，Legado 的 `java.ajax` + `JSON.parse` 无法直接解析
- **图片加密**：每页图片 XOR 加密，需要 `encryption_key` 字段解密
- **速率限制**：frank_mangaplus 文档提到"~10 requests in a few seconds"触发锁号，默认 500ms/请求间隔（源码实证：client.rs `min_request_interval: Duration::from_millis(500)`）
- **必需 Header**：`User-Agent: okhttp/4.12.0`，参数需 `os=android&os_ver=36&app_ver=250`（源码实证：shueisha.py `__request`、client.rs）
- **付费墙**：部分章节需 `secret`（subscriber token），免费用户只能看最新几章和第一话

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://mangaplus.shueisha.co.jp",
  "ruleToc": {
    "chapterList": "@js:\n// Protobuf 无法在 Legado JS 中直接解析，需 webJs 中转\n// 此处为占位，实际需要 webJs 调用原生代码解码\nresult = [];",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": {
    "content": "@js:java.ajax('...') // 需解密图片，Legado 原生不支持"
  }
}
```
- **结论**：该站**不建议直接做 Legado 书源**。Protobuf 解析 + 图片解密在 Legado 的 Rhino JS 环境中无法完成，除非：
  1. 走 `webJs` 注入浏览器环境 fetch + protobuf.js 解码（复杂）
  2. 自建中间层 API 转 JSON（需服务器）
- 若只做"目录/元信息查询"，可接受 `webJs` 方案。

### 2.3 kisskh（.club/.org，视频 Drama 站）

**源码证据**：
- debakarr/kisskh-dl `src/kisskh_downloader/kisskh_api.py`：完整 API 客户端实现
- beorgsh/KissKH-Api `main.py`：Playwright + Cloudflare bypass + API 拦截

**URL 模式**
- 基础 API：`https://kisskh.is/api/`（也见 `.do` 域名）
- 搜索：`GET /api/DramaList/Search?q={query}&type=0`（返回 JSON 数组）
- 详情：`GET /api/DramaList/Drama/{drama_id}?isq=false`（返回 Drama 对象，含 `episodes[]`）
- 剧集列表：`GET /api/DramaList/List?page=1&type=0&sub=0&country=0&status=0&order=0&pageSize=20`
- 播放流：`GET /api/DramaList/Episode/{episode_id}.png?err=false&ts=null&time=null&kkey={kkey}`（返回 JSON，含 `Video` 字段）
- 字幕：`GET /api/Sub/{episode_id}?kkey={kkey}`

**章节列表定位**
- 详情 API 返回 `episodes[]`，每项 `{id, number, sub}`（源码实证：kisskh_api.py `Drama` model + `get_episode_ids`）
- 剧集 ID 是整数，用于后续 stream/subtitle 请求

**正文定位**
- **视频流**，非文本。`Episode/{id}.png?kkey=` 返回视频 URL（MP4/HLS）
- Legado 书源无法处理视频内容

**反爬与坑**
- **Cloudflare**：beorgsh/KissKH-Api 明确使用 Playwright 绕过 Cloudflare（`"Just a moment"` 标题检测 + 鼠标移动模拟）
- **kkey 认证**：stream 和 subtitle API 需要 `kkey` token，通过 Playwright 浏览器自动化生成（源码实证：kisskh-dl `generate_kkeys` + `kkey_utils.py`）
- **Referer**：stream 请求需 `Referer: {episode_page_url}`（源码实证：kisskh_api.py `_build_episode_referer`）
- **域名漂移**：`.is` → `.do` → `.club` → `.org`，base_url 可配置

**Legado 迁移写法**
- **结论**：该站**不适合做 Legado 书源**。原因：
  1. 视频 Drama 站，非文本阅读
  2. Cloudflare + kkey 双重防护，Legado 书源无法自动生成 kkey
  3. 即使绕过，内容为视频流，Legado 无法展示
- 若用户坚持要做"视频 Drama 信息查询"类书源，可考虑只做搜索/详情元信息，但价值有限。

### 2.4 foxaholic.com（WordPress 小说站）

**源码证据**：pes1ug23am910/novel-scraper-toolkit `foxaholic/foxaholic_full_scraper_hybrid.py`

**URL 模式**
- 详情页：`https://www.foxaholic.com/novel/{slug}/`
- 章节页：`https://www.foxaholic.com/{chapter-slug}/` 或 `/novel/{slug}/chapter-{n}/`

**章节列表定位**
- 标题页内：`li.wp-manga-chapter a`（WordPress manga 主题标准结构），回退 `div.list-chapters a`、`div.chapters a`、`ul li a`
- 最终回退：任何含 `/chapter-` 且 `/novel/` 的 `a[href]`
- 按 URL 中 `chapter-(\d+)` 数字排序（源码实证：`extract_chapter_links_from_title_page` 函数，第 1-30 行）

**正文定位**
- 主选择器：`div.reading-content`（源码实证：`extract_chapter_text_and_title_from_html` 第 1-20 行）
- 回退：`div.entry-content` → `div.post-content` → `article` → `body`
- 清洗：删 `script`、`style`、`iframe`、`ads`、`aside`、`noscript`；保留 `p`、`h2`、`h3`、`div` 文本段落

**反爬与坑**
- **Cloudflare**：源码显式检测 `"checking your browser"`、`"cloudflare"`、`"access denied"`、`"ddos-guard"`，并有 cloudscraper 回退（源码实证：`is_cloudflare_blocked_text` + `ThreadedFetcher` 类）
- **Referer**：HEADERS 带 `Referer: https://www.foxaholic.com`（源码实证：第 15-25 行）
- **限速**：异步并发 2 + 随机延迟 0.6-1.4s，指数退避重试（源码实证：`ASYNC_CONCURRENCY = 2`、`safe_sleep`）
- **状态恢复**：`state.json` 记录 `last_completed`，支持断点续传

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.foxaholic.com",
  "header": "{\"Referer\":\"https://www.foxaholic.com\",\"User-Agent\":\"Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36\"}",
  "ruleToc": {
    "chapterList": "li.wp-manga-chapter a",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": {
    "content": "div.reading-content, div.entry-content, div.post-content"
  }
}
```
- **待实测**：Cloudflare 在 Legado 的 WebView 环境中是否自动通过；若不过，需 `webJs` 用 cloudscraper 逻辑绕过（复杂）。
- 章节顺序：源码按 URL 中 chapter 数字排序，CSS 选择器顺序通常已正确，无需 `reverse`。

### 2.5 mangago.me（多域名漫画站，Selenium 驱动）

**源码证据**：Yui007/mangago_downloader `src/search.py`、`src/downloader.py`、`src/models.py`

**URL 模式**
- 搜索：`https://www.mangago.me/r/l_search/?name={query}&page={N}`
- 详情页：`https://www.mangago.me/read-manga/{slug}/`
- 章节页：`/chapter/{id}/{chapter_num}/`（多页子页：`{url}/{page_num}/`）
- 多域名支持：`www.mangago.me`、`www.mangago.zone`、`www.youhim.me`

**章节列表定位**
- 搜索页 `#search_list li` → `h2 a`（标题+链接）、`.row-3.gray`（作者）、`.row-5.gray a.chico`（最新章节）
- 详情页（mangago.zone）：`#chapter_table tbody tr` → `a.chico`（章节链接+标题）
- 详情页（mangago.me）：需 Selenium 点击"show all chapters"按钮（`showAllChapters()`），源码显式处理（`downloader.py` `get_chapter_list`）
- 章节编号：正则 `Ch\.?\s*(\d+(?:\.\d+)?)` 或 URL `/chapter/\d+/(\d+)/`

**正文定位**
- mangago.me 多页漫画：`.multi_pg_tip.left` 显示总页数，每页 `img#page{i}` 或 `img.page{i}`
- 垂直长条漫画（manhwa）：单页多图，`img[id^='page']`、`img[class^='page']`、`img[src*='mangapicgallery.com']`
- manhwa 分页：`/pg-{n}/` 或 `/c{chapter_id}/{page}/` 模式
- 图片 Referer：需 `Referer: https://www.mangago.zone/` 或章节页 URL（源码实证：`_download_image`）

**反爬与坑**
- **Selenium 依赖**：搜索和详情页均需浏览器驱动，`page_load_strategy = "eager"` + 5s 等待懒加载
- **懒加载图片**：`img.loaded`（搜索结果封面）、`img[src]` / `img[data-src]`（章节内容）
- **多域名差异**：mangago.me 与 mangago.zone 的章节列表结构不同，需分别处理
- **反爬不明确**：无显式 Cloudflare 检测，但 Selenium 本身即为反反爬手段

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.mangago.me",
  "ruleToc": {
    "chapterList": "#chapter_table tbody tr a.chico",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": {
    "content": "@js:\n// Selenium 逻辑无法在 Legado 中运行\n// 若章节为单页图片：\nlet imgs = [];\nlet sel = 'img[id^=page], img[class^=page], img[src*=mangapicgallery.com]';\nlet doc = org.jsoup.Jsoup.parse(java.ajax(baseUrl));\nfor(let el of doc.select(sel)) {\n  let src = el.attr('src') || el.attr('data-src');\n  if(src) imgs.push(src);\n}\nresult = String.join('\\n', imgs);"
  }
}
```
- **待实测**：Legado 对漫画图片的展示能力；`webJs` 能否模拟 Selenium 的懒加载滚动。
- 该站更适合做"漫画元信息/目录查询"，完整漫画下载在 Legado 中成本极高。

### 2.6 wattpad.com（沿用 Round 1 §3.1）

**现状**：先例文档已有完整记录，无需重复。

**关键结论**：
- 搜索/发现：无站内搜索适配（分类 API `api/v3/categories` 可用于发现）
- 目录：`api/v3/stories/{storyId}` 返回 `parts[]` 或 HTML `ul.table-of-contents`
- 正文：`div[data-p-id]`（每段一个，Legado 逐章请求时只能拿第 1 页）
- 反爬：Mature 成人门、HTTP 405 当 403、限速 3000ms
- 迁移：CSS + `@js:` API 回落双流

### 2.7 quotev.com（沿用 Round 1 §3.2）

**现状**：先例文档已有完整记录，无需重复。

**关键结论**：
- 目录：`div#rselect a`（跳过 `javascript:`）或 `div#footer_pages select option`
- 正文：`div#rescontent`
- 无反爬
- 迁移：纯 CSS 可行

## 5. 总体判断

| 站点 | 适合风格 | 防护等级 | 建议 |

| **quotev** | CSS 纯流 | 🟢 极低 | 沿用 Round 1 结论 |
