# CSS / Jsoup 书源规则速查

> 面向阅读（Legado）书源规则的简明速查：选择器怎么写、提取后缀取什么、索引怎么定位、正则怎么清洗、什么时候该混 JS。
> 规则语义以官方阅读规则机制为准；本机工坊沙箱、官方 App、不同阅读分支的解析器版本并不完全一致，正式使用前请在目标环境实测（见第九节）。

## 一、一条规则由什么组成

```
[模式前缀] 选择器 [@提取后缀] [##正则##替换] [JS 段]
```

| 写法 | 作用 |
| --- | --- |
| `@css:...` | 整条规则按标准 CSS 解析（jsoup select），支持 `:contains`、`:not`、`:nth-child` 等；只在一条规则最开头写一次 |
| `@@...` | 等价于不加前缀（默认模式） |
| `//...` 或 `@XPath:` | XPath |
| `$.…` 或 `@Json:` | JSONPath |
| `@js:` / `<js>…</js>` | JS 段；写在选择器之后时，`result` 是前面选择器的结果 |
| `##正则##替换` | 对已取到的结果做替换；替换为空时可只写 `##正则##` |
| `##正则##替换###` | 只替换第一个匹配 |

组合规则：`&&` 表示都要（结果按顺序拼接），`||` 表示取第一个有结果的分支，`%%` 表示按元素位置交错合并。`@css:` 写在整串开头时，整条规则都按 CSS 解析，所以 `||`/`&&` 的每个分支都必须是能被 CSS 解析的写法；把 `@css:` 分支和简写分支混在一起容易静默取空，多分支时按实测把 `@css:` 写全或统一改用一种模式。

区分两种清洗位置：

- 字段末尾的 `##正则##`：先提取这个字段，再清洗这一个字段。
- `ruleContent.replaceRegex`：全部正文页合并之后，再当一条规则清洗整章。

列表字段（`bookList` / `chapterList`）只写元素选择（如 `class.list@tag.li`、`@css:#list > li`），不要在这里挂 `@text`，也不要指望列表规则执行字段替换。

## 二、标准 CSS 选择器

在 `@css:` 前缀下，或在默认模式里直接写 CSS（jsoup 支持的部分）都可以用：

| 类别 | 示例 | 说明 |
| --- | --- | --- |
| 标签 | `div`、`a`、`li` | 匹配所有同名标签 |
| 类 | `.intro`、`.item.active` | 多类名连写表示同时具备；`.item .active` 是后代关系 |
| ID | `#content`、`#list` | 整页唯一 |
| 后代 / 子元素 | `#list li`、`#list > li` | `>` 只取直接子元素 |
| 相邻 / 兄弟 | `h2 + p`、`h2 ~ p` | 紧随其后的一个 / 之后所有同级 |
| 属性存在 | `a[href]`、`img[data-src]` | 只判断有没有该属性 |
| 属性值 | `a[href^="/book"]`、`a[href$=".html"]`、`a[href*="read"]`、`[data-id="12"]` | 前缀 / 后缀 / 包含 / 精确 |
| 结构伪类 | `li:first-child`、`li:last-child`、`li:nth-child(2)`、`li:not(.ad)`、`p:empty` | `:empty` 指没有子节点和文本 |
| 文本包含 | `@css:a:contains(下一页)`、`a:contains(下一页)` | 写成 `tag.a:contains(下一页)` 时，简写模式会把整串当标签名，静默取空 |

易错点：

- 多类名写成 `.list_p s`（空格在 CSS 里是后代选择器），正确写法是 `.list_p.s`。
- `*` 能用但慎用，容易把导航、页脚一起卷进来。
- 选择器命中 0 条不报错，只是结果为空；先核对源码里的真实 class/id，再怀疑规则语法。

## 三、提取后缀：取什么

| 后缀 | 取到的内容 | 说明 |
| --- | --- | --- |
| `@text` | 元素及其子元素的可见文本 | jsoup 用空格连接各段；多元素命中时如何拼接随版本不同，正文别依赖它 |
| `@ownText` | 只取当前元素自己的直接文本 | 排除子元素里的文字，适合“标签 + 值”混排的字段 |
| `@textNodes` | 当前元素的直接文本节点 | 多个节点换行拼接 |
| `@html` | 元素自身的 HTML（含容器标签与子标签） | 多数实现会先移除 `script` / `style`，但只删标签不保证删掉里面的文本，各版本不一致 |
| `@all` | 元素自身的 HTML，不做过滤 | 与 `@html` 的差别主要就是有没有剥 `script` / `style`，以实测为准 |
| `@href`、`@src`、`@data-src` | 同名属性的值 | 懒加载图片常把真地址放在 `data-src` / `data-original` |
| 不写后缀 | 默认按 `@text` 处理 | 仅限 `@css:` 分支；默认简写模式必须写 `@` |

补充：

- 正文优先“容器 + `@html`”或“容器 + `@text`”，再交给格式化与 `replaceRegex` 清洗；不要为了通用兜底去遍历整页最大文本块。
- 取图片地址用 `@src` / `@data-src`，不要从 `@html` 里再抠字符串。
- `select@value` 这类“在 select 上取 value”取不到，把规则落到具体选项上（`option@value`）。
- `@href` 一般返回页面里的原始值；URL 型字段（书籍、章节、封面、下一页）多半会按 baseUrl 补全，普通文本字段不会。相对链接拿不准时按实测结果处理，或用 JS 补全。

## 四、默认简写模式

三段式 `类型@名称@位置`，最后一截也可以换成提取后缀：

| 写法 | 对应选择 |
| --- | --- |
| `tag.div` | `div` |
| `class.item` | `.item` |
| `id.content` | `#content` |
| `text.下一页` | 自身文本包含“下一页”的元素（近似 `:contains`，但只匹配元素自身文本） |
| `children` | 直接子元素，不需要名称和位置 |
| 其他 | 原样交给 jsoup select |

示例：`id.list@tag.li`、`class.item@tag.a@href`、`class.pager@text.下一页@href`。

`text.xxx` 是简写模式独有的定位方式，也是 `:contains` 在简写下的替代方案；`@CSS:` 走纯 jsoup 时直接用 `:contains` 更直观。

## 五、索引与位置

索引写在选择器后面的一截上（`类型@名称@位置` 或 `选择器@位置`），位置一截也可以再跟提取后缀：

| 写法 | 含义 |
| --- | --- |
| `.0` / `.-1` | 第 1 个 / 最后一个 |
| `!0` | 排除第 1 个 |
| `!0:2` | 排除第 1、3 个 |
| `[0]`、`[-1]` | 与 `.0` / `.-1` 等价 |
| `[1:4]`、`[1:4:2]` | 区间（两端都含）/ 带步长；省略起点表示从头、省略终点表示到尾 |
| `[!0:2]` | 排除区间（`[!...]` 与 `!...` 两种排除写法语义不同，按实测选） |
| `[-1:0]` | 区间反向，整段倒置 |
| 规则最前加 `-` | 结果列表整体倒置，如 `-class.chapterlist@li`、`-@css:#list li` |

需要特别注意：

- 索引属于阅读的简写模式，`@css:` 分支走纯 jsoup，不认 `.0` / `!0` 这类位置；要按序号取元素，在 CSS 里用 `:first-child`、`:nth-child(2)`、`:nth-of-type(2)`。
- `tag.li!0:2`（`!` 接区间）与 `tag.li[!0:2]` 命中的元素个数不同，别把两种排除写法混用。
- 索引越界会被跳过，不会报错。

目录倒序优先用规则前置 `-` 或区间反向，比在 JS 里 `reverse()` 更稳；列表的位置筛选同理，能写索引就不要写循环。

## 六、正则清洗

- `选择器@text##正则##替换`：只清洗这个字段。
- `##正则##`：把匹配内容替换为空。
- `##正则##替换###`：只替换第一处匹配。
- `replaceRegex`：写成 `##正则##`，作用于合并后的整章正文；不要写成选择器，也不要用贪心到文末的写法（`[\s\S]*?` 优于 `.*$`），否则会把后续内容一起吃光。
- 正则里的替代文本引用分组用 `$1`、`$2`；不同实现支持的语法略有差异，复杂替换先实测。
- 正则中要出现 `@`、`##` 或 JS 时注意分隔符会被先切开；确实需要 `##` 字面量时放进 `<js>` 段里。

## 七、和 JS 混排

- 选择器之后接 `<js>…</js>`：`result` 是前面选择器的结果；以 `@js:` 开头则是整段 JS。
- `result` 可能是 Java 对象或列表，先 `String(result)` 或 `'' + result`，再调字符串方法；列表型规则（`nextTocUrl`、`nextContentUrl`）尤其要先转字符串。
- 块内最后一行就是返回值，不要写顶层 `return`。
- 用 `var`，不要用 `const`：Rhino 里块级作用域不可靠，循环中容易取到同一个值。
- `java` 已被阅读替换，原生 Java 类走 `Packages.java.*`。
- 能静态取到的字段优先 CSS/XPath，只有在签名、加密参数、动态接口、WebView 场景才用 JS 组织请求与数据。
- JS 里解析 HTML 时优先 `java.getString('选择器@text', html)`；直接调用 Jsoup 在部分沙箱不可用，跨环境要另行验证。

## 八、三个中性例子

以下 DOM 均为示意，不对应任何真实站点。

### 1. 列表页

```html
<ul id="list" class="book-list">
  <li class="item"><h3><a href="/book/1.html">示例书甲</a></h3><span class="author">作者甲</span></li>
  <li class="item"><h3><a href="/book/2.html">示例书乙</a></h3><span class="author">作者乙</span></li>
</ul>
```

```text
标准 CSS 版
bookList:  @css:#list > li.item
name:      h3 a@text
author:    span.author@text
bookUrl:   h3 a@href

默认简写版
bookList:  id.list@tag.li
name:      tag.h3@tag.a@text
author:    class.author@text
bookUrl:   tag.h3@tag.a@href
```

### 2. 详情页

```html
<div class="book-info">
  <h1 class="title">示例书甲</h1>
  <p class="meta">作者：<span class="author">作者甲</span> · 连载</p>
  <div class="intro"><p>第一段简介</p><p>第二段简介</p></div>
</div>
```

```text
name:  @css:h1.title@ownText      -> 示例书甲
meta:  @css:p.meta@text           -> 作者：作者甲 · 连载
author:@css:p.meta span.author@text -> 作者甲
intro: @css:.intro@text           -> 第一段简介 第二段简介
intro: @css:.intro@html           -> <div class="intro">…<p>第一段简介</p><p>第二段简介</p></div>
```

`ownText` 只拿元素自身文本，`text` 会带上子元素文本，选错会把相邻字段一起吞进来。`@html` 返回的是元素自身的 HTML（含容器标签），需要纯文本就别用 `@html`。

### 3. 正文页与章节内分页

```html
<div id="content"><p>正文第一段</p><p>正文第二段</p></div>
<div class="pager"><a href="/book/1/2.html">下一页</a></div>
```

```text
content:        @css:#content@html
nextContentUrl: @css:.pager a:contains(下一页)@href
简写替代:       class.pager@text.下一页@href
replaceRegex:   ##本章完[^\n]*##
```

`nextContentUrl` 只表示同一章的下一页（文案是“下一页”“下页”），不能写成“下一章”“下一回”；没有分页就留空。

## 九、运行时差异，必须实测

同一份规则在本机工坊、官方 App、不同阅读分支上可能表现不同，以下是最容易踩到的差异点：

- `@text` 命中多个元素时，有的实现全部拼接，有的只取第一个。
- `@html` 对 `script` / `style` 的处理不一致：有的整块移除，有的只去标签，正文里可能残留样式文本。
- `:contains`、`:not`、结构伪类在简写模式和 `@css:` 下的支持程度不同。
- 相对 URL 是否自动补全，取决于字段类型和运行版本。
- 同名 JS API 的参数、返回值、可用性可能与目标阅读版本不同；沙箱能跑不代表真机能跑，反之亦然。

调试建议：

1. 用调试界面查看搜索、详情、目录、正文各阶段源码，确认选择器命中的是预期节点。
2. 用 `java.log()` 打印中间变量，先确认“取到了什么”，再改规则。
3. 规则命中 0 条不会报错，先用最小 DOM 片段复现，再回到整页排查。
4. 验收跑完四条链路：搜索（带关键词）、详情、目录、正文；正文抽查首章、末章和带分页的章节。
