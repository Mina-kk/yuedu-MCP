> **定位**：本文件只提供**候选站名单、选择器线索与实测方法**，不提供任何站点「搜索通/不通」「可用/不可用」的结论。任何站点的搜索、详情、目录、正文能否命中，都必须由使用者**在当前网络、当前日期**重新 `fetch_page` / `check_source(refresh=true)` 取证。

## 2. 每个候选怎么实测（四段各记一次）

对上面任意一个站，按同一流程拿到本轮证据，不要引用别处结论：

| 阶段 | 入口 | 取证 |
|---|---|---|
| 搜索 | 站内搜索 URL + 关键词 | 列表非空、书名/作者能对上、链接可继续流转 |
| 详情 | 搜索命中或已知详情 URL | 书名、作者、封面、简介、分类 |
| 目录 | 详情页目录入口 | 章节列表非空、章节 URL 可打开 |
| 正文 | 目录中的章节 URL | 正文节点有内容、分页/翻页规则成立 |

- 用 `fetch_page` 拿快照，`analyze_html`/`inspect_rule` 在快照上验选择器，`debug_source` 逐阶段调试，`check_source(auto=true, refresh=true)` 做最终联网验收。
- 拿不到证据的阶段标 unknown 或「待实测」，不写成「该站不能做」。遇到验证墙按 `references/verification.md` 处理，不因此给站点定性。
- 一个站的一次结果只属于那一次：换网络、换日期、换出口都要重测。

## 3. 选择器与结构线索（供本轮重测参考）

以下是**历史轮次里记录过的结构线索**，只用来减少盲试，不保证当前仍成立：

- 侧边栏/列表卡片、`h1` 标题、作者链接、`img` 封面、简介容器、标签链接是常见英文站详情页结构。
- 目录常见两种来源：HTML 表格/列表（`tr` 或 `li` 逐行取 `a@text`/`a@href`），或详情页内嵌的 JSON 数组（`@js:` 解析后拼章节 URL）。
- 正文常见一个主容器 `div` + 多个段落节点；有分页时优先 `nextContentUrl` 规则，不要手写循环。
- 具体某个站的选择器写法见 `references/english-sites.md` 的「历史选择器参考」，同样需要当日复核。

## 5. 接口画像（反推材料，不是站点结论）

适配器源码能看出「这类站点大致用什么接口」，用来判断迁移成本：

- 纯 DOM 站：css 流即可，成本最低。
- JSON API 站：可用 `@js` 流或 json 规则，需确认分页与鉴权。
- 需要浏览器态/防护重的站：先评估 WebView + webJs 能否过，再决定投入。
- 二进制协议（protobuf）或图片加密：Legado 原生 JS 成本很高，属高投入方向。
- 视频站：不属于文本阅读范围。

**接口画像不匹配只说明没有结构化快捷通道，不等于页面失效。** 网页能不能开、规则能不能命中，一律以本轮实测为准；也不要把「根路径返回 200」当成书源可用。

## 6. 发现源与写法纪律

- 发现源：FMHY reading 页及索引站 wotaku.wiki、everythingmoe.com、theindex.moe、openslum.org、ravebooksearch.com。第三方存活标注同样需要自测。
- 采集机出口被 CF/geo 拦截是**采集环境**现象，不能外推到用户网络，也不能当作站点当前状态。
- 汇报写法：写「本轮在哪个网络、哪一天、实测到哪几段」；**不写「该站搜索通/不通」这类固定结论**，未实测阶段一律 unknown。
