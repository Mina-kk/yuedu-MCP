# 阅读官方规则地图与搜索地址模式

> 本文由《阅读3.0 手机书源教程分规则讲解》蒸馏整理；规则以官方为准，权威参考：https://mgz0227.github.io/The-tutorial-of-Legado/ 。做任何书源前先读本文，规则字段名、必填选填、搜索地址格式均不得凭记忆发挥。

## 一、书源规则字段地图（官方字段，按页面分组）

### 基本页
| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 源url（bookSourceUrl） | 必填 | 具有唯一性，同名新建会覆盖旧的 |
| 源名称（bookSourceName） | 必填 | 不要求唯一 |
| 书籍URL正则（bookUrlPattern） | 选填 | 搜索直跳详情页、或想用"添加网址"加书时必填 |
| 源分组 / 源注释 | 选填 | 分组用英文逗号分隔多个组 |
| 登录URL / 登录UI / 登录检查JS | 选填 | 登录三件套；登录检查JS 写 js |
| 封面解密 / 图片解密 | 选填 | 右上角三点帮助里有示例 |
| 请求头（header） | 选填 | 影响该书源所有请求，必须是合法 JSON 字符串 |
| 变量说明 / 并发率 / jsLib | 选填 | 见源变量设置与三点帮助 |

### 搜索页（要搜索就必填）
- 搜索地址（searchUrl，必填）、校检关键词（选填，站点少字符搜索无结果时单独设置）
- 搜索列表（ruleSearch.bookList，必填）、书名规则、书名/简介等规则
- 详情页URL规则（必填；不填或没取到会用搜索地址的网址）

### 发现页（要发现就填）
- 发现地址（exploreUrl）：`名称1::网址&&名称2::网址` 或换行分隔；也支持 JSON 格式
- 发现列表（ruleExplore.bookList）：不填则沿用搜索页规则；填了就用发现页规则

### 详情页（选填，但"添加网址"从详情页开始解析，建议填）
- 预处理规则（选填，限定源码范围）
- 书名规则（搜索直跳详情页或走 bookUrlPattern 时必填）
- 作者/简介等规则；允许修改书名作者（填 1 允许详情页覆盖搜索页结果）
- 目录URL规则（ruleToc.chapterList 与详情页同页则不填）
- 下载URL规则（仅书源类型为文件时走，不进目录/正文）

### 目录页
- 更新之前JS（选填，目录url常变时用js重取）
- 目录列表（必填）、章节名称（必填）、章节URL规则（必填，没取到用目录地址）
- 格式化规则（选填，js；变量 title=章节名、index=序号、gInt 从 0 开始）
- 章节信息、Volume/VIP/购买标识（选填）
- 目录下一页规则（选填，有下一页必填，可取链接或链接数组）

### 正文页
- 正文规则（ruleContent.content；不填则返回章节链接本身，音频源常用）
- 章节名称规则（选填，加载正文时替换章节名）
- 正文下一页URL规则（选填，有下一页必填）
- webViewJs（选填：章节链接加 webView 才启用，用网站自身 js 解密，必须有返回）
- 资源正则（选填，配 webView，一般音频源用）
- 替换规则（## 或 js；作用于全部正文加载完并格式化后的纯文本）
- 图片样式：FULL 铺满 / DEFAULT 原始 / TEXT 同文字大小 / SINGLE 每页一张
- 购买操作（选填，js；返回链接文本则网页加载，返回 true 则更新目录重载正文）

## 二、搜索地址（searchUrl）知识

### 编码识别
- UTF-8：源码头部 `charset="utf-8"`，一字 3 字节 = 3 个 %（我 → %E6%88%91）
- GBK：`charset="gbk"` / `gb2312`，一字 2 字节 = 2 个 %（我 → %CE%D2）

### GET 搜索（地址栏直接有关键词）
- `http://www.example.com/s/{{key}}`（utf-8）
- `http://www.example.com/s/{{key}},{"charset":"gbk"}`（gbk）
- 可不写域名用源URL：`/s/{{key}}`

### POST 搜索（地址栏没有关键词，常见搜索后变成 searchid 数字）
分析 form 表单：`method` 定请求方法，`action` 定网址；**只看带 name 的 input/select**，`名字=值` 用 & 拼接，关键词替换为 `{{key}}`：

```
/s.php,{
    "method":"POST",
    "body":"keyword={{key}}&t=1"
}
```

gbk 站加 `"charset":"gbk"`；同样可以不写域名。获取途径：① 手析 form；② 抓包看请求体；③ 把 form 源码投喂 AI 按上述格式生成。

### webView 模式（动态加载站点）
网站内容靠 js 延迟渲染、或查看搜索源码见"加载中"时，给搜索地址加 `{"webView":true}`（可与 method/body/charset 组合）。

## 三、调试方法（官方 App 内调试）

- **看源码**：调试界面右上角三点 → 搜索/书籍/目录/正文源码
- **java.log()**：`@js:java.log(result|src|baseUrl)`，打印中间变量，最常用排错手段
- **链接前缀调试**：发现链接 `名称::http://...` 或 `::http://...`；详情页链接直接贴网址；目录链接前缀 `++`；正文链接前缀 `--`
- 反馈解析失败的标准流程：自查是否用了 java.io/安卓专属类（不兼容分支的不用报）→ 开调试导出日志 → 书源文件+日志一起提交，注明"原版能跑、本版本不行"

## 四、列表规则三种标准语法

同一段 HTML，官方认可的标准写法只有三类，生成规则时优先用标准语法（default 是阅读自创的 css 变体，缺斤少两时也能解析，但不标准）：

| 语法 | 识别方式 | 示例 |
| --- | --- | --- |
| JSOUP default（阅读变体） | `id.x@class.y` / `tag.p!0:-1` | `id.list@class.list_p`、`class.list@tag.p!0:-1` |
| CSS（通用标准） | `@css:` 开头或标准 css | `@css:#list .list_p.s`、`@css:#list>p:not(:first-child)` |
| XPath（通用标准） | `//` 或 `@XPath:` 开头 | `//div[@id='list']/p[@class='list_p s']` |

常见错误：多类名写成 `.list_p s`（空格在 css 里是后代选择器），正确是 `.list_p.s`。

## 五、做源顺序提醒

1. 先 `match_sources(域名)` 查语料，有同域/同族源做底本；
2. 抓包/看源码确认编码、GET/POST、是否动态加载；
3. 按上面字段地图逐段写规则，列表规则用标准语法；
4. 调试用 `++`/`--` 前缀逐段验证，`java.log` 打印中间结果；
5. 验收跑 `check_source`。
