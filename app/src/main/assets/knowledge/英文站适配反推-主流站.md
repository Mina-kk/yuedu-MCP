> 研究日期：2026-09-21
> 研究对象：WebToEpub（TypeScript 浏览器扩展）+ FanFicFare（Python 下载器）的站点适配代码
> 目标：为一批英文小说/漫画站制作 Legado 书源，从成熟下载器反推规则写法

## 2. Legado 规则语法备忘（迁移用）

- CSS 选择器 = **jsoup 语法**：`tag.class`、`#id`、`[attr=val]`、`a[href*=/chapters/]` 等都可用；属性取值用 `@href` `@text` `@html` `@src` `@content` `@data-original`。
- 正文多段：官方行为是多个匹配元素/多段 **按 `\n` 拼接**（`ruleContent.content` 匹配到的元素全部拼接）。
- JS：规则值以 `@js:` 开头或整段用 `<js>...</js>`；JS 环境提供 `java.ajax(url)`（GET 请求返回字符串）、`JSON.parse`、`baseUrl`、`book`、`source` 等；复杂 HTML 再造可用 `org.jsoup.Jsoup.parse(html).select(...)` 得到元素列表再交给 `chapterName`/`chapterUrl` 的 CSS 规则（目录 JS 的常规写法，个别版本行为略有差异时以实际 App 为准）。
- 目录翻页：`ruleToc.nextTocUrl` 是**在当前目录页上找"下一页"链接的 CSS 选择器**（不是 URL 模板）；站点不给翻页链接时只能 `chapterList` 用 `@js:` 自己循环翻页。
- 清洗：`ruleContent.replaceRegex`（对正文文本做正则替换）适合去掉广告水印段；元素级清洗用 `@js:`/`<js>`。
- 请求头：书源 `header` 字段可全局带 `Referer`/`Cookie`/`UA`；Legado 无逐源"延迟"字段，秒级限速只能靠调低全局并发 + 减少单章请求次数来规避。
- 适配器概念 → Legado 字段对应：`getSiteURLPattern`→`bookSourceUrl`+`ruleBookInfo`；`extractChapterUrlsAndMetadata`→`ruleBookInfo`+`ruleToc`；`add_chapter`→`ruleToc.chapterList/-Name/-Url`；`findContent/getChapterText`→`ruleContent.content`；`removeUnwantedElements`→`replaceRegex`/`webJs`。

## 3. 分站点笔记

### 3.1 wattpad.com（双仓库覆盖）

**URL 模式**
- 详情页：`https://www.wattpad.com/story/{storyId}`（FanFicFare 从 URL 提 storyId；邮件通知里的跳转链接 `www.wattpad.com/{chapterId}` 也能反查：先请求 `/v4/parts/{chapterId}?fields=group(id)` 拿 `group.id` 即 storyId）
- 章节页：`https://www.wattpad.com/{chapterId}`（URL 里只有章节数字 ID）
- API：故事信息 `GET https://www.wattpad.com/api/v3/stories/{storyId}`（含 `parts[]`：title/url/createDate/photoUrl，及 `mature`/`completed`/`cover`/`tags` 等元信息）；正文 API `GET https://www.wattpad.com/apiv2/storytext?id={chapterId}`；分类 API `GET https://www.wattpad.com/api/v3/categories`
- 搜索页：适配器未涉及（分类 API 可用于分类发现）

**章节列表定位**
- FanFicFare：纯 API——`api/v3/stories/{storyId}` 返回的 `storyInfo['parts']` 直接就是章节列表（title + url）
- WebToEpub：优先抓详情页 HTML `ul.table-of-contents`（超链接列表）；抓不到才回落 API `api/v3/stories/{storyId}` 的 `json.parts`

**正文定位**
- FanFicFare：API `apiv2/storytext?id={chapterId}` 直接返回 HTML 片段（`imgdata + data`，章节横幅图 photoUrl 拼在前面）
- WebToEpub：`div[data-page-number]`；长章节有多页：页面 `<script>` 里找 `.metadata":{"data":` 附近的 JSON，取 `text_url.text`（URI 模板）、`text_url.refresh_token`、`pages`，第 2..N 页请求 `{uriStart}-{page}{uriEnd}`；抓回来按 `p[data-p-id]` 去重（多页间段落会重复）

**反爬与坑**
- Mature 作品有成人门（FanFicFare 直接抛 `AdultCheckRequired`；API 的 `mature` 字段）
- WebToEpub 遇到 HTTP 405 按 403 处理（wattpad 对异常请求返回 405）
- WebToEpub 限速 3000ms/请求；翻页 token 失效要用 refresh_token 重取
- 元信息：title `div.story-info span.sr-only`；author `div.af6dp a`；简介 `div.glL-c`；封面 `div[data-testid='cover'] img`；标签 `div._9c7jH a`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.wattpad.com",
  "ruleBookInfo": {
    "name": "div.story-info span.sr-only@text",
    "author": "div.af6dp a@text",
    "intro": "div.glL-c@text",
    "coverUrl": "div[data-testid='cover'] img@src",
    "tocUrl": ""
  },
  "ruleToc": {
    "chapterList": "ul.table-of-contents li a",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": { "content": "div[data-p-id]" }
}
```
- 目录页无 `ul.table-of-contents` 时，`chapterList` 改 `@js:`：`java.ajax("https://www.wattpad.com/api/v3/stories/" + storyId)` → `JSON.parse` → `parts[]`（title/url）构造目录（可用 `org.jsoup.Jsoup.parse` 拼 `<a>` 列表）。
- 正文 `div[data-p-id]`（每段一个）比 `div[data-page-number]` 更稳——多页章节 Legado 逐章请求时只能拿到第 1 页，`data-p-id` 选择器至少保证第 1 页段落完整；长章节多页拼接在 Legado 里成本高，建议接受只抓首页或评估 `webJs` 二次 ajax 追加。

### 3.2 quotev.com（双仓库覆盖）

**URL 模式**
- 详情页：`https://www.quotev.com/story/{storyId}`（`url.split('/')[4]` 即 ID）
- 章节页：`{详情页}/{章节文件名}`（FanFicFare 从 `div#rselect a` 拿相对地址 urljoin）
- 搜索页：适配器未涉及

**章节列表定位**
- FanFicFare：`div#rselect a`（跳过 `javascript:` 伪链接），文本为章节名，href 为章节地址
- WebToEpub：`div#footer_pages select` 的 `option`——`value` 是相对章节路径、文本是章节名；没有 select 说明是单章作品

**正文定位**
- FanFicFare：`div#rescontent`（并把 quizHeader 里的章节头图、`img#resultImage` 的 onclick 里藏的图片插到正文前；正文内 `<a>` 全部 unwrap 成纯文本）
- WebToEpub：`div#quizResArea`（外层容器）

**反爬与坑**
- 基本无反爬；坑是"单章/多章"两种结构要分别处理
- 元信息：title `div.result h1`（FFF）/ `div#quizHeaderTitle h1`（WTE）；author `div.quizAuthorList a`；简介 `div#qdesct`；封面 `meta[property=og:image]@content` 或 `div#quizResArea` 首图；状态看元信息行是否含 `· Completed`；发布时间在 `<time ts=...>` 属性里

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.quotev.com",
  "ruleToc": {
    "chapterList": "div#rselect a",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": { "content": "div#rescontent" }
}
```
- 若站点改版只剩 `div#footer_pages select`：`chapterList` 用 `@js:` 取 `org.jsoup.Jsoup.parse(java.ajax(baseUrl)).select("div#footer_pages select option")`，再把 `value`（相对路径）拼成绝对 URL。
- 正文里的超链接在 Legado 中默认保留，可用 `replaceRegex` 或 `<js>` 去链；插图（resultImage 的 onclick 藏图）Legado 抓不到，需 `webJs` 特判，优先级低可放弃。

### 3.3 royalroad.com（双仓库覆盖）

**URL 模式**
- 详情页：`https://www.royalroad.com/fiction/{storyId}`（FFF 从 path `/fiction/(\d+)` 提 ID）
- 章节页长格式：`/fiction/{storyId}/{storyTitle}/chapter/{chapterId}/{chapterTitle}`；短格式 `/fiction/chapter/{chapterId}`（只有 chapterId 是有效的）
- 标签搜索：`/fictions/search?tagsAdd={tag}`（WTE 从页面上 `a.fiction-tag` / `a[href*='tagsAdd=']` 反推）；适配器不做站内搜索页

**章节列表定位**
- FanFicFare：详情页 `table#chapters tbody tr` → 每行 `td a`（章节链接+标题）、`td time[unixtime]`（日期）
- WebToEpub（更新、更抗改版）：页面 HTML 里的 **`window.chapters = [...]` JSON 数组**（每项 `id/title/slug/url`）是唯一在三种改版形态下都存在的常量，优先解析它；抓不到再回落 `table#chapters`。注意浏览器端目录会被"显示链接数"截断，必须重新拉整页

**正文定位**
- FanFicFare：`div.chapter-inner.chapter-content`（作者注 `div.author-note-portlet` 用 `find_previous/find_next` 塞进正文首尾）
- WebToEpub：`div.chapter-inner` 的**父元素**（改版后 wrapper 没了）；回落 `div.portlet-body`（含 chapter-inner 的）→ `.page-content-wrapper`

**反爬与坑**
- 404 页返回 HTTP 200：判断 `div.number` 文本 == `404`
- **隐藏水印**：正文 `<p>` 带 `cn[A-Z][a-zA-Z0-9]{41}` 随机 class，由内联 `<style>` 的 `display:none` 控制——抓取时必须按 style 规则把这些元素删掉（FFF 和 WTE 都专门处理）
- 剧透框 `div.spoiler`（FFF 可配置删除/转 fieldset）
- 无需登录（登录仅用于标记已读）
- 元信息：title `div.fic-header h1`（WTE 改版后用 `div.fic-header div.col h1`）；author `div.fic-header a[href^='/profile/']` 或 `meta[property=books:author]@content`；简介 `div.fiction-info div.description`（或 JSON-LD `Book.description`，或 `meta[property=og:description]`）；封面 `meta[property=og:image]@content`（新版）或 `img.thumbnail`；标签 `a.fiction-tag`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.royalroad.com",
  "ruleToc": {
    "chapterList": "table#chapters tbody tr td a",
    "chapterName": "@text",
    "chapterUrl": "@href",
    "nextTocUrl": ""
  },
  "ruleContent": { "content": "div.chapter-inner" }
}
```
- RR 页面改版频繁（旧 table / 新 Tailwind 表格无 id / JS 空壳），CSS 可能失效。稳健做法：`chapterList` 用 `@js:` 抓 `window.chapters`：
  `let html = java.ajax(baseUrl); let m = html.match(/window\.chapters\s*=\s*(\[[\s\S]*?\]);/); JSON.parse(m[1])` → 每项 `url`/`title`（无 url 时拼 `/chapter/{id}/{slug}`）。
- 水印：`replaceRegex` 删不掉（要靠元素删除），用 `webJs`/`@js:` 按 class 模式删除；或退而求其次用 `replaceRegex` 匹配 `cn[A-Z][a-zA-Z0-9]{41}` 残留空行。`display:none` 的元素 jsoup 不执行 CSS，**删不掉**，这是 RR 迁移最大的坑，务必实测。
- 作者注：想要就 `content` 选 `div.chapter-inner` 的父容器并手动保留 `div.author-note-portlet`；嫌烦就只选 `div.chapter-inner`。

### 3.4 scribblehub.com（双仓库覆盖）

**URL 模式**
- 详情页：`https://www.scribblehub.com/series/{storyId}/{任意标题}/`（FFF 正则 `/(series|read)/(?P<id>\d+)`；从 `link[rel=canonical]` 拿权威 URL）
- 章节页：`https://www.scribblehub.com/read/{storyId}-{storyTitle}/chapter/{chapterId}/`
- 附加页：`{详情页}stats/`（FFF 抓统计）
- 搜索页：适配器未涉及

**章节列表定位**
- FanFicFare：WordPress AJAX——**POST** `https://www.scribblehub.com/wp-admin/admin-ajax.php`，表单 `action=wi_getreleases_pagination&pagenum=-1&mypostid={storyId}`，返回 HTML 里取 `a.toc_a`；且必须先下 cookie **`toc_sorder=asc`** 才能拿到正序（默认倒序）
- WebToEpub：直接抓详情页 HTML 的 `a.toc_a`，配合 `span.cnt_toc`（总章数）翻页：`{详情页}?toc=1,2,3...` 直到攒够总章数（站点有时会漏返章节，要防死循环）；拿到的列表 `.reverse()` 转正序

**正文定位**
- FanFicFare：`div#chp_raw`（作者注 `div.wi_authornotes`、公告 `div.wi_news`、剧透 `div.sp-wrap` 都在里面，可分别删除/重排）
- WebToEpub：`div.fic_row, div#chp_raw`

**反爬与坑**
- **章节页校验 Referer**：WTE 用 declarativeNetRequest 给章节请求强塞 `Referer: {目录页URL}`——直连章节页可能被拒
- 限速极重：WTE 设 5200ms/请求（目录翻页期间才临时降到 500ms）
- FFF 注释提到 AJAX 偶发 400（配 flaresolverr 时出现），暗示可能有 Cloudflare 类防护
- 目录默认倒序（见上）；章节标题在 `div.chapter-title`；简介 `.wi_fic_desc`（要删 `.dots/.morelink`、展开 `.testhide`）；封面 `div.fic_image img`；标签 `a.fic_genre`（体裁）/`a.stag`（fandom）

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.scribblehub.com",
  "header": "{\"Referer\":\"https://www.scribblehub.com/\"}",
  "ruleToc": {
    "chapterList": "a.toc_a",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": { "content": "div#chp_raw" }
}
```
- 顺序：页面目录是新的在前，需要反转。CSS 选择器无法反转，用 `chapterList` `@js:`：`org.jsoup.Jsoup.parse(java.ajax(baseUrl)).select("a.toc_a")` 后 `.reverse()` 再返回（或接受倒序后手动排序，不推荐）。
- 翻页：`?toc=N` 若目录页上有分页链接，直接 `nextTocUrl` 选它；没有就 `@js:` 循环 `java.ajax(baseUrl + "?toc=" + i)` 直到章节数达到 `span.cnt_toc`。
- Referer 必须在书源 `header` 里带上（至少指向域内页面），否则章节页可能空。
- FFF 的 POST AJAX 方案（含 `toc_sorder=asc` cookie）在 Legado 里性价比低（POST/下 cookie 都麻烦），优先用 WTE 的 HTML+`?toc=` 方案。

### 3.5 novelfire.net（仅 WebToEpub）

**URL 模式**
- 详情页：`https://novelfire.net/novel/{novel-slug}`（从 `dom.baseURI` 推）
- 目录页：`{详情页}/chapters`
- 章节页：`{详情页}/chapter-{n_sort}`（n_sort 是章节排序号，见下）
- 同源码站点：`boxnovel.art` 用同一个 parser；`novelfire.docsachhay.net` 走 LightNovelWorldParser

**章节列表定位**
- 首选（DataTables AJAX）：在 `/chapters` 页的 `<script>` 里找含 `/listChapterDataAjax` 的片段，取出该 URL 后补 DataTables 参数（`draw=1`、`order[0][column]=2&dir=asc`、`length=-1` 即全量）请求，返回 JSON 的 `data[]`，每项 `title` + `n_sort`，章节 URL = `{root}/chapter-{n_sort}`
- 回落（HTML）：`/chapters` 页 `ul.chapter-list a`（`.chapter-title` 章节名、`.chapter-no` 章号），翻页链接在 `ul.pagination li a`（`?page=N`）

**正文定位**（继承自 LightNovelWorldParser）
- `div.chapter-content`，回落 `div#content`

**反爬与坑**
- 水印：父类逻辑删「任何带 class 的 `<p>`」、嵌套 `<strong>`、`div>dl>dt` 的父级——迁移时用 `@js:`/`webJs` 做元素级删除
- DataTables 参数一长串，`@js:` 里要原样拼（见 WTE 源码 buildChapterListRequestUrl）
- 元信息：title `div.novel-info h1`；author `span[itemprop=author]`；封面 `meta[property*=og:image]@content` 回落 `div.header-body` 首图；章节标题 `span.chapter-title`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://novelfire.net",
  "ruleToc": {
    "chapterList": "ul.chapter-list a",
    "chapterName": ".chapter-title@text",
    "chapterUrl": "@href",
    "nextTocUrl": "ul.pagination li a@href"
  },
  "ruleContent": { "content": "div.chapter-content, div#content" }
}
```
- 优先用 HTML 回落方案（`/chapters` 页），配 `nextTocUrl` 翻页；`ul.pagination` 的链接若为 JS 伪链接则 `@js:` 循环 `java.ajax(root + "/chapters?page=" + i)`。
- AJAX 全量方案（`listChapterDataAjax` + `length=-1`）适合章节极多、翻页痛苦的站：`chapterList` `@js:` 从 `/chapters` 页 HTML 正则出 `/listChapterDataAjax...` 片段 → 补全参数 → `java.ajax` → `JSON.parse(res).data` → 拼 `{title, url: root + "/chapter-" + n_sort}`。
- 章名拼接：`linkToChapterIfo` 的逻辑是「标题不含 chapter 且有章号时，章号+": "+标题」，`@js:` 里照抄即可。

### 3.6 novelcool.com（仅 WebToEpub）

**URL 模式**
- 详情页：`https://novelcool.com/novel/{slug}` 类页面（代码未硬编码，从 `dom.baseURI` 取）
- 章节页：目录页 `a` 的 href 直接给
- 搜索页：适配器未涉及

**章节列表定位**
- `.chapter-item-list a`，每条的标题在子元素 `span.chapter-item-headtitle`；**页面顺序是新的在前，代码整体 `.reverse()`**

**正文定位**
- `.chapter-reading-section-list`，回落 `.overflow-hidden`
- 清洗：删 `.chapter-end-mark`（"本章结束"标记）和 `.chapter-section-report`

**反爬与坑**
- 目录倒序（同上，需 JS 反转）
- 元信息：title `h1.bookinfo-title`；author `.bookinfo-author a`；封面 `.bookinfo-pic` 首图；简介 `.bk-summary-txt`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://novelcool.com",
  "ruleToc": {
    "chapterList": "@js:\nlet els = org.jsoup.Jsoup.parse(java.ajax(baseUrl)).select(\".chapter-item-list a\");\nresult = els.toArray().reverse();",
    "chapterName": "span.chapter-item-headtitle@text",
    "chapterUrl": "@href"
  },
  "ruleContent": { "content": ".chapter-reading-section-list, .overflow-hidden" }
}
```
- 不在意章序的话 `chapterList` 可直接 `.chapter-item-list a`、`chapterName` 用 `span.chapter-item-headtitle@text`。
- `replaceRegex` 可加一条清理章节尾标记残留文本。

### 3.7 freewebnovel.com（仅 WebToEpub）

**URL 模式**
- 详情页：`https://freewebnovel.com/novel/{slug}`（代码从 baseURI 去 query/hash 得基础 URL）
- 章节页：目录 `ul#idData` 里 `a` 的 href
- 目录翻页 AJAX：`{详情页}?ajax=chapters&page={N}` → **返回 JSON** `{code:200, html:"<章节a片段>"}`（不是 HTML 页）
- 总页数来源：`#indexselect` 的 option 个数，或页面 script 里的 `totalPage: N`
- 同源码站点：bednovel.com / innnovel.com / libread.com；novellive.com 等用子类（不同目录结构）

**章节列表定位**
- 首页 `ul#idData` 全部 `a`；`totalPage>1` 时循环请求 `?ajax=chapters&page=2..N`，把返回 JSON 的 `html` 字段再解析出链接

**正文定位**
- `div#article`，回落 `div.txt`

**反爬与坑（这家坑最多）**
- 广告注入：`div[id^='bg-ssp-']`、`div[id^='pf-']`（SSP/PubFuture 联盟），删完还要删空壳 div
- **文本内逃逸 HTML**：`&lt;strong&gt;` 这类字面量出现在文本节点里，要二次解析还原
- **混淆水印**：用 NFKD 归一化后匹配 `reewebnovel`（变体字符伪装），从文本里删；`freewebnovel.com` 专享清洗：删 `p sub` 子元素、删含 "this story originates from" / "ensure the author gets the support" 的整段
- 限速 1000ms
- 元信息：title `h1.tit`；author `[title=Author]` 父节点的 `a`；封面 `div.pic` 首图；章节标题 `span.chapter`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://freewebnovel.com",
  "ruleToc": {
    "chapterList": "ul#idData a",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": {
    "content": "div#article, div.txt",
    "replaceRegex": "(?i)this story originates from.*?\\n|ensure the author gets the support.*?\\n"
  }
}
```
- 翻页：`?ajax=chapters&page=N` 返回 JSON，`nextTocUrl` 用不了，需要 `chapterList` `@js:` 循环 `java.ajax(url + "?ajax=chapters&page=" + i)` → `JSON.parse(res).html` → 拼链接（或用 `org.jsoup.Jsoup.parse` 解析片段）。
- 水印段用 `replaceRegex` 正则删（Legado 对最终文本做替换，正好治 "originates from" 类整段）；`reewebnovel` 字符伪装水印也只能用 `replaceRegex` 兜底（元素级 NFKD 归一化在 Legado 里难做）。
- 广告 div：`webJs` 里 `document.querySelectorAll("div[id^='bg-ssp-'],div[id^='pf-']").forEach(e=>e.remove())` 或接受少量广告残留。

### 3.8 lightnovelworld.org（仅 WebToEpub）

**URL 模式**
- 详情页：`https://lightnovelworld.org/novel/{novelName}`（**从 URL path 提 novelName**，代码里 `url.match(/\/novel\/([^/]+)/)`）
- 章节页：`/novel/{novelName}/chapter/{number}/`（number 来自 API 的 `chapter.number`，URL 是拼出来的，不是页面链接）
- 目录 API：`GET https://lightnovelworld.org/api/novel/{novelName}/chapters/?offset=0&limit=500`（500 是上限，超出也按 500）→ `{chapters:[{title, number}], has_more:bool}`
- 搜索页：适配器未涉及

**章节列表定位**
- 纯 API：offset 从 0 开始、每页 500、`has_more` 为假即停，全量拉完拼章节列表

**正文定位**
- `.chapter-content`

**反爬与坑**
- 无反爬迹象；但**没有 HTML 目录页可依赖**（该 parser 完全走 API），Legado 侧必须 `@js:` 发请求
- 元信息：title `.novel-title`；author `.novel-author`（去掉 "Author: " 前缀）；简介 `.summary-content`；封面 `.novel-cover-container` 首图；章节标题 `.chapter-title`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://lightnovelworld.org",
  "ruleContent": { "content": ".chapter-content" }
}
```
`ruleToc.chapterList` 用 `@js:`：
```js
let name = baseUrl.match(/\/novel\/([^/]+)/)[1];
let all = [], offset = 0;
for (;;) {
  let json = JSON.parse(java.ajax("https://lightnovelworld.org/api/novel/" + name + "/chapters/?offset=" + offset + "&limit=500"));
  all.push(...json.chapters);
  if (!json.has_more) break;
  offset += 500;
}
let sb = "";
for (let c of all) sb += '<a href="https://lightnovelworld.org/novel/' + name + '/chapter/' + c.number + '/">' + c.title + "</a>";
result = org.jsoup.Jsoup.parse(sb).select("a");
```
- 注意 API 的 `number` 是章节号字段，URL 模板 `/novel/{name}/chapter/{number}/` 必须原样复刻。
- 兄弟站点（lightnovelcave.com、lightnovelworld.com/.co、novelpub.com、webnovelpub.com/.pro、pandanovel.co、novelbob.org、novelphoenix.com、lightnovelpub.fan）共用 `LightNovelWorldParser`：HTML 目录页 `{详情页}/chapters` + `ul.chapter-list a` + `ul.pagination` 翻页，正文 `div.chapter-content || div#content`——做这批站时直接复用 §3.5 的 HTML 方案即可，无需 API。

### 3.9 archiveofourown.org（双仓库覆盖）

**URL 模式**
- 作品页：`https://archiveofourown.org/works/{workId}`（也认 `ao3.org`、`archiveofourown.com/.net/.gay`、`download.*` 等镜像域；合集内 `/collections/{name}/works/{id}`）
- 章节页：`/works/{workId}/chapters/{chapterId}`
- **目录页（关键）：`{作品页}/navigate`**（真正的整章链接列表在这里）
- 系列页：`/series/{seriesId}?page=N`
- 成人内容：URL 加 `?view_adult=true`；整作模式 `?view_full_work=true`
- 搜索页：适配器未涉及（系列翻页逻辑在 base_otw 的 get_series_from_page）

**章节列表定位**
- FanFicFare：拉 `{作品页}/navigate`，章节链接 = `a[href*="/works/{workId}/chapters/"]`，日期取链接旁的 `span.datetime`（AO3 允许作者乱序插章，还要比较日期找"最新章"）
- WebToEpub：作品页上有 `li.chapter` 元素 → 从 `ul#chapter_index a` 拿 navigate 页地址 → navigate 页 `ol.chapter a` 列表；单章作品直接用作品页 URL；系列页 `ul.series.work > li` 逐作品处理（`dd.chapters a` 转成对应 /navigate）
- WTE 给每个章节 URL 都强塞 `view_adult=true`

**正文定位**
- FanFicFare：单章页 `div.userstuff module`；整作页（`?view_full_work=true`）按 `div#chapter-{N}` 切分。周边元素：作品开头注 `div.preface.group div.notes.module blockquote.userstuff`、章节简介 `div#summary blockquote`、章节注 `div#notes blockquote`、章节尾注 `div.end.notes.module blockquote`、作品尾注 `div#work_endnotes`
- WebToEpub：`div#chapters`（单章页 AO3 把正文包在 `div#chapters` 里）；删 `h3.landmark.heading`

**反爬与坑**
- 成人门：不登录时 adult 作品直接不显示，需 `?view_adult=true`（且老版本该参数对基础作品页失效，要追"Proceed"链接）
- 登录墙：仅注册可见作品必须登录（token 来自 `GET /token_dispenser.json`，POST `/users/login`）
- 伪 503：返回体里有 `<h2 class="heading">Error 503 - Service unavailable</h2>`（HTTP 状态码并不是 503）；beta 公告页也要识别
- 元信息：title `h2.heading`；author `a[rel=author]`；标签 `.meta .tags a`；简介 `div.summary blockquote`；语言 `meta[name=language]@content`

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://archiveofourown.org",
  "ruleBookInfo": {
    "name": "h2.heading@text",
    "author": "a[rel=author]@text",
    "intro": "div.summary blockquote@text",
    "tocUrl": "@js:baseUrl + \"/navigate?view_adult=true\""
  },
  "ruleToc": {
    "chapterList": "ol.chapter a",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": { "content": "div#chapters, .userstuff" }
}
```
- `tocUrl` 用 `@js:` 拼 `/navigate`（若你的 Legado 版本 tocUrl 不支持 JS，就退而求其次：`chapterList` 直接选作品页上的章节导航，或手动建书时把目录页 URL 当详情页）。
- 成人内容：在书源 URL/header 层面带 `view_adult=true`（Legado 对查询参数支持不好时，可让用户登录态 Cookie 走 `header`）。
- 作者注/简介块：默认全收（`div#chapters` 会带上前言注），嫌乱就 `content` 只选 `.userstuff` 再用 `webJs` 精确取。
- 系列页做书：`chapterList` 选 `ul.series.work > li h4.heading a` 只能拿到作品级链接，多作品合并成"一本书"需要 `@js:` 逐作品再拉 /navigate，成本高——建议系列页直接放弃或按单作建书。

### 3.10 fanfiction.net（双仓库覆盖）

**URL 模式**
- 详情页/首章页：`https://www.fanfiction.net/s/{storyId}/1/`（FFF 接受 `m.` 移动域但归一化到 `www.`；章节 URL 带标题 slug 可选）
- 章节页：`/s/{storyId}/{chapterNum}/`（FFF 从 `select[name=chapter]` 的 option value 拿章号**拼 URL**；WTE 从 select 的 `onchange` 属性里拆出路径模板再拼）
- 搜索页：适配器未涉及

**章节列表定位**
- FanFicFare：`select[name=chapter] option`（value=章号、文本=章名），URL 自己拼 `/s/{id}/{value}/{urltitle}`；没有 select 就是单章
- WebToEpub：`select#chap_select option` + 父 select 的 `onchange`（`self.location='...'+value+'...'`）拼路径；单章作品直接当前页
- 注意：**两个仓库的章节链接都不是现成 href，必须拼接**

**正文定位**
- FanFicFare（更新）：`div#storytextp`
- WebToEpub：`div.storytext`（旧 class 名）
- 当前 ffnet 实际 HTML 是 `<div class="storytextp" id="storytextp">`，以 FFF 的 `div#storytextp` 为准、`div.storytext` 做回落

**反爬与坑**
- 限速：WTE 3050ms/请求（ffnet 对快速请求会 5xx）
- URL slug 失效：带标题的章节 URL 有时 404，两个工具都有"去掉 slug / 去掉末尾斜杠"重试逻辑——**Legado 侧最稳的做法是章节 URL 不带 slug**：`/s/{id}/{num}/`
- 广告：`div.google-auto-placed`（flaresolverr 场景下出现的内联广告）
- 元信息：title `div#profile_top b`；author `div#profile_top a`（href `/u/{id}`）；简介 `div#profile_top div.xcontrast_txt`；元数据行 `div#profile_top span.xgray`（Rated/Language/Genre/Chapters/Words/... 用 ` - ` 分隔，日期在 `span[data-xutime]` 属性里）；封面 `div#img_large img@data-original`（FFF 用 `img.lazy.cimage@data-original`）

**Legado 迁移写法**
```json
{
  "bookSourceUrl": "https://www.fanfiction.net",
  "ruleToc": {
    "chapterList": "@js:\nlet doc = org.jsoup.Jsoup.parse(java.ajax(baseUrl));\nlet id = baseUrl.match(/\\/s\\/(\\d+)/)[1];\nlet opts = doc.select(\"select#chap_select option\");\nlet sb = \"\";\nfor (let o of opts) sb += '<a href=\"https://www.fanfiction.net/s/' + id + '/' + o.val() + '/\">' + o.text() + '</a>';\nresult = org.jsoup.Jsoup.parse(sb).select(\"a\");",
    "chapterName": "@text",
    "chapterUrl": "@href"
  },
  "ruleContent": { "content": "div#storytextp, div.storytext" }
}
```
- 纯 CSS 做不到 URL 拼接（option 没有 href），必须 `@js:` 构造；这也顺带解决了"URL 不带 slug"的稳定性问题。
- `replaceRegex` 清理谷歌广告残留与 `google-auto-placed` 空段落。
- 封面/简介/元信息选择器见上，`span.xgray` 的元数据行可按 ` - ` 分割提取。
